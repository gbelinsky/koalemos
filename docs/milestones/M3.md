## Component Architecture

### Dependency Tree

```
Level 0: Cache Foundation
├── ScreenshotCache (GenServer) - In-memory image storage
├── DOMStateCache (GenServer) - Parsed DOM structure
├── ConsoleCache (GenServer) - Console logs
└── VariableStateCache (GenServer) - Variable snapshots

Level 1: Core Logic
├── JavaScript Hook (canvas-based screenshot capture)
├── HTMLParser (extract semantic structure from HTML)
└── JavaScriptExtractor (extract scripts, handlers, functions)

Level 2: Integration
├── Screenshot Tool (PubSub: request → JS → cache → retrieve)
├── Parser Integration (HTML → parse → caches)
└── PubSub Channels (coordination)

Level 3: UX Polish
├── Compact config display (next to title)
├── Provider-specific panels (Ollama models, API keys)
└── Enhanced modal (validation, persistence)
```

### Component Responsibilities

**ScreenshotCache** (~150 lines)
- GenServer for in-memory storage
- Base64 PNG images
- Operations: put(id, image), get(id), clear(id), clear_all()
- Supervision tree integration
- TTL/size limits (optional for MVP)

**JavaScript Hook: ScreenshotCapture** (~400 lines total - 2 sprints)
- Mounted: Setup iframe listeners
- Canvas-based capture (html2canvas or manual)
- PubSub: Send screenshot to Elixir
- Debouncing/throttling
- Error handling

**Screenshot Tool** (~100 lines)
- Tool definition in TestLens
- Execute: Sends PubSub request to JS
- Waits for capture completion
- Retrieves from ScreenshotCache
- Returns image in tool result (content blocks format)

**HTMLParser** (~500 lines, simplified from Flo's 38KB)
- Uses Floki for HTML parsing
- Extract semantic structure:
  - Headings (h1-h6)
  - Forms (inputs, buttons, selects)
  - Interactive elements (links, buttons)
  - Metadata (ids, classes, data-attributes)
- Basic error handling
- Returns structured map

**JavaScriptExtractor** (~200 lines)
- Extract inline <script> blocks
- Extract event handlers (onclick, etc)
- List defined functions
- Returns: `%{scripts: [...], handlers: [...], functions: [...]}`

**DOMStateCache** (~150 lines)
- GenServer storing parsed DOM
- Operations: put(routine_id, dom), get(routine_id)
- Cleared on routine completion

**ConsoleCache** (~150 lines)
- GenServer storing console logs
- Operations: append(routine_id, log), get(routine_id)
- Cleared on routine completion

**VariableStateCache** (~150 lines)
- GenServer storing variable snapshots
- Operations: put(routine_id, vars), get(routine_id)
- Cleared on routine completion

## Integration Points

### PubSub Topics

**Screenshot Communication:**
- `screenshot:request:#{routine_id}` - Elixir → JS: request screenshot
- `screenshot:captured:#{routine_id}` - JS → Elixir: screenshot ready
- Events: `%{routine_id: string, image: base64, timestamp: DateTime}`

**LiveView Hook:**
- Hook name: `ScreenshotCapture`
- Listens for: `phx:screenshot:request`
- Sends: `phx:screenshot:captured` with base64 image

### State Management

**ScreenshotCache:**
- Key: routine_id (string)
- Value: %{image: base64, captured_at: DateTime}
- TTL: Until routine completes

**DOMStateCache:**
- Key: routine_id
- Value: %{elements: [...], metadata: %{}}

**ConsoleCache:**
- Key: routine_id
- Value: [%{type: :log, message: "...", timestamp: ...}]

**VariableStateCache:**
- Key: routine_id
- Value: %{var_name => value}

### Event Flow

**Screenshot Workflow:**
```
AI calls screenshot tool
  ↓
Tool sends PubSub request (screenshot:request:routine_id)
  ↓
JS Hook receives request
  ↓
Hook captures iframe → canvas → base64
  ↓
Hook sends PubSub event (screenshot:captured:routine_id)
  ↓
LiveView receives event
  ↓
LiveView stores in ScreenshotCache
  ↓
Tool retrieves from cache
  ↓
Tool returns image in content blocks
  ↓
AI receives screenshot
```

**Parsing Workflow:**
```
User uploads HTML (future feature)
  ↓
HTMLParser.parse(html)
  ↓
Parser extracts semantic structure
  ↓
Store in DOMStateCache
  ↓
JavaScriptExtractor.extract(html)
  ↓
Store scripts in cache
  ↓
Lens queries caches for context
  ↓
Context includes DOM structure + JS
```
